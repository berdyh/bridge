# @berdyh/bridge

The `bridge` command line, and the package people install with `npx @berdyh/bridge setup <app-url>`. `setup` installs the runner, connects the machine to an app and pairs a browser in one go. The other commands are `connect`, `run`, `enroll` (including `enroll approve` and `enroll deny`), `status`, `browsers`, `apps`, `agent` (`login`, `logout`, `status`), `plugin`, `doctor`, `service`, `self install`, `uninstall` and `protocol` (the `bridge://` link handler, Linux). `bridge --help` lists them with their flags. The CLI runs the local runner for every app the machine is connected to. It is for people who use an app built on the kit, and for the agents that set it up for them. Its functions (`runCli`, `startRunner`) can be embedded with injected dependencies such as custom agent adapters. See [Operate the runner](../../docs/guides/operate-the-runner.md) and [Write an adapter](../../docs/guides/write-an-adapter.md).
